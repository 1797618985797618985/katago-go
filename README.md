# 围棋对战程序 · KataGo

## 这是什么

以 [KataGo](https://github.com/lightvector/KataGo) 为棋力内核的围棋对战程序。核心特点：

- **两种对战模式**：人机对战、同设备人人对战
- **33 档难度**：采用中国围棋协会业余段级位 —— 级位 25级～1级 + 业余段位 1段～8段，
  逐档调节搜索与拟人化参数 —— 详见 [关于级位与段位](#关于级位与段位)
- **真正离线**：引擎是本地子进程，程序零 npm 依赖，前端不引用任何 CDN；断网后一切照常
- **自适应硬件**：自动探测可用的引擎构建与实测算力，纯 CPU 机器也能跑（自动切换到轻量权重）
- **为实体棋盘留好接口**：落子 / 提子 / 复位 / 对齐等事件已抽象成电机指令，接上控制器即可驱动实体电驱棋盘

```
┌──────────────────────────────────────────────────────────┐
│  浏览器界面（Canvas 棋盘 / 难度选择 / 数子 / 提示音）      │
└───────────────────────────┬──────────────────────────────┘
                            │ REST + SSE（本机，不联网）
┌───────────────────────────▼──────────────────────────────┐
│  Node.js 服务端（零依赖）                                  │
│   ├─ 规则引擎   提子 / 劫 / 禁全同 / 让子 / 数子 / SGF      │
│   ├─ 引擎管理   KataGo GTP 子进程 × 2（普通 + 人类风格）    │
│   ├─ 内置引擎   纯 JS 蒙特卡洛，无 KataGo 时的兜底          │
│   └─ 硬件桥接   棋局事件 → 电驱棋盘指令                     │
└───────────────────────────┬──────────────────────────────┘
                            │ GTP / JSON 行协议
┌───────────────────────────▼──────────────────────────────┐
│  KataGo（OpenCL / CUDA / CPU） + 训练好的神经网络权重      │
└──────────────────────────────────────────────────────────┘
```

## 功能特性

### 对局

- 人机对战：可选执黑 / 执白、让子 2～9 子、贴目、中国规则 / 日本规则
- 人人对战：同一台设备轮流落子
- 悔棋（人机模式自动回退到自己的回合）、停一手、认输、提示（AI 给点）
- 连续两次停手自动进入**数子阶段**：点击棋块标记死子，实时显示两种规则的比分
- 导出 SGF 存档

### 规则引擎

- 提子、自杀手禁止、**简单劫 + 位置型禁全同（超级劫）**
- 让子摆放遵循传统顺序（角 → 边 → 天元）
- 中国规则数子法 / 日本规则数目法双算，同时给出结果
- 9 / 13 / 19 路棋盘

### 交互

- **违规落子三重反馈**：禁止落子 + 提示音 + 弹窗提示 + 棋盘抖动、非法点闪红圈
- 悬停预览：合法点显示半透明棋子，非法点显示红色叉
- 最后一手标记、坐标显示、星位、动画提示点、AI 思考指示
- 提示音全部由 Web Audio 现场合成，**不依赖任何音频文件**
- 键盘快捷键：`P` 停一手、`U` 悔棋、`H` 提示、`S` 数子、`N` 新对局

## 快速开始

### 1. 获取引擎与权重（只需联网一次）

```powershell
pwsh -File tools/fetch-engine.ps1
```

脚本会下载到 `engine/` 目录：

| 内容 | 说明 |
| --- | --- |
| `engine/bin/opencl/` | KataGo OpenCL 版，**只依赖显卡驱动**，兼容性最好 |
| `engine/bin/cuda/` | KataGo CUDA 版，装了 CUDA + cuDNN 时速度最快 |
| `engine/bin/cpu/` | Eigen 纯 CPU 版，没有独显时的兜底 |
| `engine/models/` | 训练好的权重（主权重 / 人类风格 / 轻量） |

> **KataGo 不需要自己训练。** 官方分布式训练项目（[katagotraining.org](https://katagotraining.org/networks/)）
> 产出的 `.bin.gz` 权重就是可直接使用的成品，下载即可。

### 2. 启动

```bash
npm start
```

然后打开 <http://127.0.0.1:8080>。

首次启动如果走 OpenCL，会做一次 GPU 内核调优（可能几分钟），之后会缓存，启动只需几秒。

### 3. 完全离线

第 1 步完成之后，程序**不再访问任何网络**：

- 引擎是本地进程，通过标准输入输出对话
- 没有 CDN、没有外部字体、没有 npm 依赖（`dependencies` 为空）
- 界面所需的全部资源都在 `public/` 目录

## 难度分级

### 关于级位与段位

围棋的等级体系并不只有一套，"能到几级、几段"取决于用哪个体系：

| 体系 | 级位 | 段位 |
| --- | --- | --- |
| **中国围棋协会（本程序采用）** | **业余 25级 ～ 1级** | **业余 1段 ～ 8段**（1～7 段为常规段位，8 段为荣誉段位） |
| 日本棋院 / KGS / OGS | 30级 ～ 1级 | 业余最高 8 段；线上平台通用到 9 段 |
| 线上平台（弈城 / 野狐 / Tygem） | 18级 ～ 1级 | 1段 ～ 9段 |

> 现实中的**业余**段位一般只到 7 段；8 段是荣誉段位（授予世界业余围棋锦标赛冠军等），
> 9 段则是**职业**段位的上限，因此本程序不把"业余 9 段"作为难度档位。

本程序采用中国围棋协会的业余段级位：**级位 25级～1级 + 业余段位 1段～8段，合计 33 档**。

难度曲线本身是 0～38 的归一化刻度，与 KataGo 人类风格模型的档位范围
（`rank_20k` ~ `rank_9d`）一一对应；档位数与曲线刻度相互独立，
所以调整段级位范围不会打乱难度分布。

如果你希望改成"业余只到 7 段"，把 `server/engine/levels.js` 里的 `DAN_MAX` 改成 7 即可，
难度曲线会自动重新分布；同理把 `KYU_MAX` 改成 30 就变成 30 级制。

### 33 档难度是怎么定的

每一档都不是简单地"改一个数字"，而是同时调节 KataGo 的多个维度：

| 难度 | 访问数 | 思考上限 | PDA | 策略温度 | 人类风格档位 | 建议让子 |
| --- | --- | --- | --- | --- | --- | --- |
| 25级 | 1 | 0.5s | 5.0 | 3.00 | rank_20k | 9 子 |
| 20级 | 2 | 0.5s | 4.5 | 2.87 | rank_20k | 6 子 |
| 15级 | 3 | 0.55s | 3.8 | 2.61 | rank_18k | 6 子 |
| 10级 | 8 | 0.74s | 2.9 | 2.17 | rank_12k | 4 子 |
| 5级 | 27 | 1.18s | 2.0 | 1.63 | rank_6k | 2 子 |
| 1级 | 107 | 2.07s | 1.1 | 1.19 | rank_1k | — |
| 1段 | 196 | 2.50s | 0.9 | 1.12 | rank_1d | — |
| 3段 | 472 | 3.55s | 0.5 | 1.00 | rank_3d\* | — |
| 6段 | 2438 | 7.67s | 0.2 | 1.00 | 主权重搜索 | — |
| 8段 | 6000 | 14.0s | 0.0 | 1.00 | 主权重搜索 | — |

\* 3 段及以下使用**人类风格模型**（拟人化走法），4 段及以上切换为主权重的深度搜索。
分界点由 `config.json` 的 `katago.humanModelMaxIndex` 控制（默认 33，对应 3 段）。

- **PDA**（playoutDoublingAdvantage）：正值让引擎自我削弱
- **策略温度**：越高落子越随机，避免每盘棋一模一样
- 表格中间的档位由分段线性插值生成，完整数据见 [`server/engine/levels.js`](server/engine/levels.js)

### 自适应算力

程序启动时会**实测**引擎吞吐（访问数/秒），再据此决定：

| 实测吞吐 | 采用的权重 | 可稳定支持的难度 |
| --- | --- | --- |
| ≥ 500 次/秒（独显） | 主权重 `b18c384nbt` | 直到 8 段 |
| 60～500 次/秒 | 主权重 / 轻量权重 | 由实测值反推 |
| < 60 次/秒（纯 CPU） | 自动切换到轻量权重 `b6c96` | 级位为主 |
| 没有 KataGo | 内置 JS 引擎 | 约到 5 级 |

反推依据是"单步思考不超过 8 秒"，结果会显示在界面顶栏，超出本机能力的档位会标注 ⚠。

## 硬件：实体电驱棋盘

程序已经把驱动电机的接口留好了，棋局事件会被翻译成机械动作指令：

| 棋局事件 | 下发指令 | 说明 |
| --- | --- | --- |
| 新开一局 | `reset` | 清空棋盘 |
| 落子 | `place` | 落子 + 本次提子一次性下发，控制器自行安排取子/落子顺序 |
| 停一手 | `pass` | — |
| 悔棋 / 跳转 | `sync` | 直接让棋盘与软件状态对齐，避免逐手倒推出错 |
| 终局 | `end` | 附带结果文本，可用来驱动显示屏/语音 |
| 提示 | `led` | 可选，硬件有 LED 阵列时点亮建议点 |

反向也支持：控制器上报 `{"event":"button","x":15,"y":3}` 时，实体棋盘上的落子会直接驱动界面。

开启方式（`config.json`）：

```json
{
  "hardware": {
    "enabled": true,
    "driver": "tcp",
    "tcp": { "host": "192.168.1.50", "port": 9100 }
  }
}
```

可选驱动：`none`（默认）、`log`（写日志模拟，用于联调）、`tcp`（ESP32 / 树莓派）、
`stdio`（本机串口桥接脚本）。完整协议见 [`docs/hardware-protocol.md`](docs/hardware-protocol.md)。

## 常见问题

**Q：一定要有独立显卡吗？**
不需要。程序会自动检测：有独显就用 OpenCL/CUDA 跑主权重；只有 CPU 就自动换成轻量权重
`b6c96`；连 KataGo 都没有时退回内置 JS 引擎。只是纯 CPU 上高段位会比较慢，界面会标注出来。

**Q：需要自己训练模型吗？**
不需要。官方权重是训练好的成品，`tools/fetch-engine.ps1` 会直接下载。

**Q：CUDA 版启动报错？**
多半是没装 cuDNN（表现为缺少 DLL）。不影响使用 —— 程序会自动改用 OpenCL 版；如果想用 CUDA，
去 NVIDIA 官网装好 CUDA Toolkit 与对应版本的 cuDNN 即可。

**Q：能和真实棋盘连吗？**
可以，接口已经准备好了。见 [docs/hardware-protocol.md](docs/hardware-protocol.md)。
